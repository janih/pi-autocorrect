# Project rules — pi-autocorrect

- This is a pi agent extension. Entry point: `index.ts` (default-exported factory receiving `ExtensionAPI`). Support code lives in `lib/`.
- `lib/` must stay dependency-free (no pi imports) so tests can run with `node --test` / plain `node` using native type stripping.
- Relative imports use explicit `.ts` extensions (matches pi's official extension examples and jiti).
- `dict/british-english` is user-provided; do not edit.
- `dict/british-english` is gitignored (652K user data); after a fresh clone, provide it as described in README.md before tests will pass.
- `dict/tech-words.txt` is GENERATED by `tools/update-tech-dict.mjs` (`npm run update-dicts`); never hand-edit it — personal/project words go in `dict/custom-words.txt` or the user's `~/.pi/agent/pi-autocorrect.json`.
- Run `npm test` and `npm run typecheck` after changing `lib/` or `index.ts`.
- `npm test` runs every `test/*.test.mjs`. UI wiring is tested by driving the extension with a fake `ExtensionAPI`/`ctx.ui` — see `test/ask-mode.test.mjs`, which sets `process.env.HOME` to a temp profile (mode `ask`) before importing `index.ts`, because the config path is resolved at import time.
- Dev loop: the repo is symlinked at `~/.pi/agent/extensions/pi-autocorrect`; after edits pass tests, run `/reload` in pi (or start with `pi -e .`).
- Git discipline: use Semantic Commit Messages with prefixes like `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`, `perf:`.
- The tokenizer intentionally skips code spans, URLs, paths, flags, and identifier-style tokens; when touching it, keep those cases covered in `test/spellcheck.test.mjs`.
- Reports and ask mode work on `groupIssues()` output, not raw issues: one question/entry per distinct (case-insensitive) word, and `expandFix()` replays the chosen correction onto every occurrence, re-casing it when the suggestion list was the source. Repeated-word runs follow the same rule via `groupRepetitions()` — one question per repeated word, collapsed in every run. Keep that behaviour when touching `processText`.
- Repeated words (`the the`) are a separate pass: `findRepetitions()` finds runs, `repetitionFix()` collapses a run to its first word. Words the spellchecker flagged are passed in as `skip` so the two passes can never produce overlapping spans, `VALID_REPEAT_WORDS` holds the legitimate same-word sequences (`had had`, `that that`, …) that must stay untouched, and `applyFixes()` drops overlapping fixes defensively (first one wins).
- `Token.plain` (prose word outside protected ranges, any length) drives repeated-word detection; `Token.check` (= plain and ≥ 3 letters) drives spell-checking. Keep both flags when touching `tokenize`.
